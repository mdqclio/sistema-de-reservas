## Diseño

- **Link público, no PDF**: `docs/voucher.html`, mismo patrón que `docs/checkin.html`: auth anónima,
  lee **solo** `/cabanas/checkin_tokens/{token}` (path puntual). No lee `/cabanas/reservas` ni escribe nada.
- **Mismo token, dos vistas**: el `checkinToken` de la reserva sirve para el pre check-in y para el voucher.

## Token (`/cabanas/checkin_tokens/{token}`)

`datosTokenReserva(r, ctx)` (pura) arma el nodo. Campos:
`reservaId, codigo, hab, tipoCabana, entrada, salida, noches, pasajeros, guestName, moneda, total,
pagado, saldo, horaCheckin, horaCheckout, datosSena, precheckinHecho, actualizado`.

- Antes el token tenía solo `reservaId, hab, entrada, salida, guestName`.
- `saldo = saldoReserva(r)`, `total = totalReserva(r)`, montos en `r.moneda`.
- **Datos del huésped: solo el nombre.** Nada de DNI, email ni teléfono (test con lista blanca de
  claves y búsqueda de esos valores en el JSON).
- `codigo`: últimos 6 caracteres alfanuméricos del id, en mayúsculas (no había código de reserva).
- `horaCheckin/horaCheckout`: de `bot_config.checkin/checkout`, default 15:00 / 10:00.

### Saldo actualizado (no congelado)

`refrescarTokenReserva(r)` reescribe el nodo si la reserva ya tiene link. Se llama en:
- `aplicarPagoReserva` → **todo cobro** (pago normal y cada reserva de un pago grupal),
- `saveReserva` al editar, `saveExtension`, `saveCambioCama`, `saveHorario`.

El voucher muestra "Montos al dd/mm/aaaa hh:mm" (momento de la última escritura).
No se refresca en el cobro del check-in porque ahí el token se borra (ver abajo).

### Ciclo de vida del token (cambio en el flujo de pre check-in)

- Antes: al **promover el pre check-in** (`promoverPrecheckin`) el token se **borraba** → con
  "mismo token" el voucher moriría justo antes de la llegada.
- Ahora: se **reescribe** con `precheckinHecho: true`. `docs/checkin.html` lee ese flag y muestra
  "¡Datos recibidos!" en vez del formulario (no se puede reenviar). El voucher sigue vivo.
- `precheckinHecho` también es `true` si la reserva ya no está `confirmada`.
- En el **check-in** (`confirmCheckin`) el token se sigue borrando como antes → el voucher deja de
  estar disponible una vez que el huésped llegó (el voucher lo explica si se abre).
- Si se genera un voucher después del check-in, se crea token nuevo con `precheckinHecho: true`
  (el form de pre check-in no se reabre).

### Reglas de seguridad (NO se tocaron)

`security/database.rules.json` (y staging, idéntico en este nodo):
```
"checkin_tokens": {
  ".write": "auth != null && auth.provider !== 'anonymous'",
  "$token": { ".read": "auth != null" }
}
```
No hay `.validate` ni lista de hijos permitidos en `checkin_tokens` → **los campos nuevos entran
en la misma regla**: escribe solo staff (no anónimo), lee cualquier autenticado (incl. anónimo) **un
token puntual**; sin `.read` en el padre, no se puede listar. Los montos quedan visibles para quien
tenga el link (token UUID no adivinable), igual que ya pasaba con nombre y fechas.

## Voucher (`docs/voucher.html`)

- Código, titular, cabaña + tipo, entrada y salida (fecha larga), noches, pasajeros.
- Pagos: Total / Pagado / Saldo. Cada fila es **un renglón flex: etiqueta a la izquierda y valor a la
  derecha, en la misma línea** (cifras tabulares). Una fila por concepto, sin filas repetidas en $0;
  saldo 0 → "Sin saldo pendiente".
- Moneda: `US$ 241,53` para USD, `$ 300.000` para ARS. El voucher no puede importar `fmtMoney` de
  `index.html` (y `fmtMoney` muestra "USD", no "US$"), así que tiene su `fmtMonto` equivalente.
- Horarios, dirección (Delfín esq. Alfonsina Storni, Mar de las Pampas), qué incluye (desayuno,
  parrilla individual, WiFi, TV, 1 estacionamiento por cabaña).
- Mobile-first, fondo claro, botón "Imprimir / Guardar PDF" (`window.print`) y CSS de impresión.
  `noindex`. Todo el texto dinámico pasa por `escapeHtml`. No muestra el `reservaId` interno.
- No se copió el formato del PMS viejo.

## Botón en el sistema

- Listado de reservas, reservas confirmadas o en check-in: botón **📄** → `enviarVoucher(rid)`:
  - Asegura el token (reusa el de la reserva o crea uno) y lo reescribe con datos actuales.
  - Con teléfono: abre `https://wa.me/<solo dígitos>?text=<saludo + cabaña + fechas + noches + link>`.
  - Sin teléfono: copia el link al portapapeles y avisa (fallback `prompt` si no hay clipboard).
  - `auditLog` en los dos casos.
- ⚠️ `wa.me` necesita el número en formato internacional (ej. `5491155551234`). Se le sacan `+` y
  espacios, pero **si el teléfono está cargado sin el 54 el link de WhatsApp no va a funcionar**.
  No se agregó normalización automática para no adivinar números.
- `generarLinkPrecheckin` ahora usa el mismo `asegurarTokenReserva` (el token lleva todos los campos).
